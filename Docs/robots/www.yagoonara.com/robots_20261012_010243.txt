# 링크 공유 미리보기 봇 — og:image 접근 허용 (2026-09-04 GSC 커버리지 감사)
#
# 왜 전용 그룹인가: 아래 `User-agent: *` 그룹의 `Disallow: /*/opengraph-image` 가 공유 카드 이미지까지
#   막고 있었다. 선수·팀 상세의 og:image 는 **동적 OG 라우트 단 하나뿐**이고 /og-image.png 폴백조차
#   없어서(파일 기반 OG 라우트가 config 지정을 이긴다), 차단되면 공유 카드에 이미지가 통째로 사라진다.
#   실측(2026-09-03 nginx 로그): 카카오톡 스크랩 봇이 하루 4,809건 요청하는데 opengraph-image 요청은
#   전 UA 합쳐 20건(카카오 4건)뿐이었다 — 차단이 실제로 먹고 있었다는 뜻.
#   robots 규칙상 전용 UA 그룹이 있으면 * 그룹을 무시하므로(bingbot 선례) 여기서만 OG 를 허용한다.
#
# ⚠️ Googlebot/bingbot 에는 계속 차단을 유지한다 — og:image 는 순위 요소가 아닌데 잠재 URL 이
#   약 27,000개(선수 6,747 + 팀 50, 4로케일)이고 렌더가 요청당 1.4초·최대 138KB 라 크롤 예산과
#   해외 대역폭만 태운다. 공유 카드에 필요한 것은 아래 봇들뿐이다.
# ⚠️ 연속 User-agent 줄은 RFC 9309 상 하나의 그룹이다(규칙이 아래 한 벌만 있으면 전부에 적용).

# 네이버 Yeti — og:image 허용 (2026-09-05 사용자 결정: "노출이 더 잘 되는 방향으로")
#
# 왜 네이버만 여는가:
#   ① 우리 검색 유입의 90%가 네이버다(2026-08 실측). 네이버 웹사이트 검색결과 카드의 썸네일이 og:image이고,
#      Yeti가 이미지를 수집하지 못하면 카드가 텍스트만 남는다.
#   ② 실측(2026-09-03 nginx): Yeti는 하루 8,543건을 크롤하면서 robots.txt를 읽고 og:image 요청은 **0건**이었다
#      — 아래 `*` 그룹의 `Disallow: /*/opengraph-image` 가 실제로 먹고 있었다는 뜻.
#   ③ 부하 상한이 작다: 동적 OG 라우트를 가진 페이지는 `/players/:id`·`/teams/:id` **루트뿐**이고
#      하위 탭(/players/:id/stats 등)은 정적 `/og-image.png`를 쓴다. Yeti가 하루에 건드리는 고유 선수 2,272명
#      + 팀 24개 = **최대 2,296 렌더/일**, 게다가 OG 라우트에 `revalidate=86400`이 걸려 있어 하루 1회로 캐시된다.
#
# ⚠️ Googlebot·bingbot에는 계속 차단한다(결정 불변):
#   구글은 og:image를 검색 썸네일 신호로 쓰지 않는데 크롤 예산이 우리의 병목이고(하루 2천건 / 알려진 URL 81만),
#   bingbot은 해외 대역폭 과금의 최대 단일 원인이라 유입 대비 비용이 맞지 않는다.
# ⚠️ 전용 그룹이라 `*` 그룹을 통째로 무시한다 → 공통 Disallow를 **`/*/opengraph-image` 하나만 빼고 전부 복제**했다.
#   (`*`에 새 Disallow를 추가하면 여기에도 추가할 것 — `npm run test:robots`가 누락을 잡는다.)
