# 1983–2000 합성 데이터 → 실측 교체 계획

Last updated: 2026-08-20

1982 시즌 실측 교체(나무위키 박스스코어, `scripts/historical/1982_namu_boxscores.py`)를
1983–2000 합성 데이터에 확장하기 위한 설계 노트. 실행은 별도 세션에서 시즌 배치로.

## 배경

- 현재 1983–2000 시즌은 합성(추정) 데이터 (`data/archives/kbo_YYYY_official.json` 소스).
- 1982 교체 결과 팀별 승패가 위키백과 최종순위와 전부 일치했고, 검증 체계(매치업
  균형·무승부·DH·재경기·유령 경기 감지)가 유효함이 확인됨.

## 파이프라인 확장 요점

1. **문서 URL 일반화**: `{팀 문서명}/{연도}년/{3~4월|5월|6월|7월|8월|9~10월}` — 팀명
   변천 매핑 테이블을 연도별로 도입. OB 9~10월 404 사례처럼 문서명/월문서 폴백
   규칙(단일 월 문서)을 유지.
2. **캘린더 불신 규칙**: 캘린더 표는 날짜 시프트(박스 대비 1일 이르게)·스코어 방향
   혼재 → 박스스코어를 진실로 취급 (1982 검증 기준).
3. **유령 경기 감지**: 동일 날짜·매치업에서 다른 스코어 + 한쪽 박스 이닝 라인이 다른
   날짜 박스와 완전 동일 → 복사 오기 (해태 4/8 사례). 시즌별 배치에서 감지 규칙
   실행 후 수동 확정.
4. **재경기 날짜 교정**: 복수 날짜 헤더("N월 D일, N월 D'일") 규칙 유지, 스타디움
   조건 매칭.
5. **검증 앵커**: 연도별 위키백과 최종순위 (경기장별 홈/원정 규칙은 확장 필요 —
   수원=쌍방울, 청주=빙그레/한화, 마산 순회 등).
6. **배치 구조**: 연도 단위 (수집 → 파싱 → 정합성 검증 → 위키 대조 → 교체). 요청
   1.5초 딜레이 시 문서 ~50개/년 → 연도당 수십 분. 병렬화는 딜레이 정책에 따라 검토.

## 산출물 관리

- raw 박스: `data/archives/{년도}_namu_raw.json`
- 정답 세트: `data/archives/{년도}_answer_set_final.json`
- 적용: 로컬 SQLite + Oracle 운영 DB 동일하게 교체 (백업 덤프 선행, `season_id`
  표준 `YYYY00` 형식 사용 — 1982에서 19820 고아값 결함 교정 완료)

## 1983 교정 기록 (2026-08-18)

`data/archives/1983_answer_set_final.json` (300경기) — 6팀 전부 위키백과 앵커와
일치 달성: HT 55-1-44, MBC 55-2-43, SM 52-1-47, SS 46-4-50, OB 44-1-55, LT 43-1-56.
적용된 수정 2건과 교정 절차를 남긴다.

### 교정 1: 9/24 OB-삼미 스코어 오기 (승패 반전)

- **문제**: 박스스코어에 OB 4 : 삼미 3으로 기록 → 우리 데이터 OB 45-1-54, SM 51-1-48
  (위키 앵커 44-1-55 / 52-1-47 대비 ±1승 어긋남).
- **증거 (6개 신호 전부 삼미 승 지지)**:
  - OB 문서 섹션 헤더: "9월 24일 VS 삼미 슈퍼스타즈 (대전) **1패**"
  - OB 문서 캘린더 9/24 셀: `삼미 4:3` (9월 캘린더 1일 시프트 — 9/25 `롯데 0:6`이
    박스 OB 6-0과 일치하므로 시프트 적용 시 9/24 = 삼미 4:3)
  - 양 팀 누적표: OB 4~8월 33-1-44 + 9월 11-0-10 = 44-1-55, SM 43-0-36 + 9월 9-1-11
    = 52-1-47 — 각각 위키백과 시즌 앵커와 일치
  - 우리 데이터 기준 단 한 경기만 뒤집으면 OB/SM 양쪽 불일치가 동시 해소
- **교정**: `19830924OBSM0` 스코어 반전 → **삼미 4 : OB 3 (삼미 승)**.
  양 문서(OB/삼미)의 박스 테이블 자체가 공통 오기 (문서 내부에서도 헤더/캘린더/
  누적표와 모순).
- **교훈**: 캘린더/섹션 헤더/누적표(상위 검증)와 박스가 모순될 때, 박스의 "R열"만
  신뢰하지 말고 이닝 라인 합·문서 내부 일관성·위키 앵커를 교차 검증할 것. (기존
  "박스스코어를 진실로 취급" 규칙의 예외 사례)

### 교정 2: 4/30 HT-MBC 유령 경기 제거 (R열 오기 복제)

- **문제**: 답변셋에 4/30 HT-MBC가 2경기 (HT 2:1 + HT 4:1, ID `HTMBC0`/`HTMBC1`) →
  HT/MBC 101경기, HT 56-1-44, MBC 55-2-44 (앵커 대비 +1승/+1패).
- **원인**: HT 문서와 MBC 문서의 4/30 박스가 같은 이닝 라인
  (HT 0 0 0 3 0 0 0 1 0 / MBC 0 0 0 0 0 0 0 0 1)인데 MBC 문서의 **R열만 오기** (HT 2).
  파서가 문서별 R열을 그대로 읽어 서로 다른 두 경기로 중복 수집 (유령 경기 패턴 —
  상위 "유령 경기 감지" 규칙의 실제 사례).
- **증거**: HT 문서 박스 R열 = HT 4 (이닝 합 4와 일치), MBC 캘린더 4/30 = `해태 4:1`,
  실재 DH라면 양 문서에 박스 2개씩 존재해야 하나 각 1개.
- **교정**: `19830430HTMBC0` (HT 2:1) 삭제, `19830430HTMBC1` (HT 4:1) → `HTMBC0`으로
  ID 재명명. HT 55-1-44, MBC 55-2-43, 총 300경기 달성.
- **교훈**: 동일 날짜·매치업의 이닝 라인이 동일한데 R열만 다르면 R열 오기로 보고
  단일 경기로 병합할 것. 후속 시즌(1984–2000) 배치에서 R열 vs 이닝 합 불일치
  감지 규칙을 파이프라인에 추가 권장.

### 참고: 최초 앵커 가정 오류

교정 전 검증에서 MBC 55-1-44, SS 50-1-49, LT 44-1-55로 오인했으나 위키백과
"1983년 한국프로야구" 실제 최종순위는 MBC 55-2-43, SS 46-4-50, LT 43-1-56 —
무승부 수가 우리 데이터(SS 4무, MBC 2무 포함 5건)와 정확히 일치. 위키백과 시즌
문서(리그 전체 최종순위표)를 앵커 소스로 사용할 것.

## 감지 규칙 파이프라인 반영 (2026-08-20)

이번 교정 2건에서 얻은 감지 규칙을 `scripts/historical/namu_season_boxscores.py`에
구현했다. 후속 시즌(1984–2000) 배치에서 동일 오류를 자동으로 걸러낸다.

- **R열 vs 이닝 합 불일치 (`r_mismatch`)**: `parse_boxes`가 각 박스의 이닝 셀 합
  (`inning_sum1/2`)을 계산하고 R열과 다르면 플래그를 남긴다. (교정 2의 4/30
  MBC 문서 사례 — 헤더 탐색 실패 시 팀명 행을 토대로 이닝 열 인덱스를 추론).
- **유령 중복 폐기**: `merge_games`가 같은 날짜·매치업에서 `r_mismatch` 박스를
  폐기하고 정상 박스만 병합한다. 모두 오기면 원본 보존 + WARN. 정상 박스가 여럿
  (서로 다른 스코어)이면 진짜 더블헤더로 유지.
- **수동 교정 테이블 (`SCORE_FIXES`)**: R열이 일관됐으나 사실과 다른 박스
  (교정 1의 9/24 OB-SM)는 `SCORE_FIXES[(연도, "MM-DD")]`에 팀코드별 최종 득점으로
  등록하고 `apply_score_fixes`가 재현 가능하게 적용한다 (1982의 `REPLAY_CORRECTIONS`
  선례). 현재 9/24 OB 3-4 SM 1건만 등록.
- **verify 진단 확장**: 팀별 앵커 대조(기존) + 매치업 최소/최대 균형 + 무승부 경기
  목록 + 불일치 팀 `delta W/L/D` + head-to-head 상호전적 + 승패 반대 부호 팀 간
  단일 스코어 반전 후보 tip. 1983 원데이터 재검증 시 301경기(유령 포함)에서
  불일치를 명확히 지적한다.
- **answer set 보호**: `--verify-only`는 파일을 절대 덮어쓰지 않는다. 일반 실행도
  verify 통과 시에만 answer set을 쓴다 (검증 실패 상태로 산출물 훼손 방지).
- **재검증 결과**: 검증 통과 상태의 300경기 answer set을 파이프라인 규칙으로
  재현 가능 — `merge_games`(유령 r_mismatch 폐기) → `apply_score_fixes` → `finalize`
  재생성 시 6팀 앵커 전부 OK, 무승부 5건 목록은 이전 수동 확정과 동일.
- **테스트**: `tests/scripts/test_historical_namu_boxscores_checks.py` — R열 오기
  감지 / 유령 폐기 / 진짜 더블헤더 유지 / 동일 스코어 중복 병합 / `SCORE_FIXES`
  적용·멱등성 / verify 진단 출력 / 1983 원데이터 재생성 일치 (15 cases).
  (후속 1985 교정으로 `DROP_BOXES` 테스트 4건 추가 — 현재 19 cases)

## 1984 배치 기록 (2026-08-20)

- **결과**: 재크롤 600박스, 삼성 포함 6팀 앵커 일치.

- 검증: game_id 중복 0, LENGTH(game_id)=13 (YYYYMMDD+홈2+원정2+슬롯),

### 구조 이슈: 삼미→청보 시즌 중 개명

- **문제**: 1985는 삼미 슈퍼스타즈(전기)가 6월 중 청보 핀토스로 개명 — 나무위키에

  CB로 정규화 (문서 원본은 team_doc 필드에 보존). 앵커 파일도 SM→CB 키로 교정.

  55경기, 총 330). 위 표는 수정 완료.

### 교정 1: 6/18·19 LT-MBC 팀 라벨 스왑 오기 (SCORE_FIXES)

- **문제**: MBC 문서의 6/18·19 박스가 이닝 라인을 롯데 문서와 동일하게 갖고 있으면서
  **팀명 행만 서로 뒤집어** "LT 3:1 MBC"(LT 승)로 기록 — merge가 스코어 시그니처
  (3,1)로 중복 판별해 잘못된 MBC 문서 버전(LT 승)만 남았다. 결과 LT +2W / MBC -2W.
- **증거**: 양 문서 섹션 헤더가 모두 MBC 2승 지지 ("피스윕"=롯데 스윕당함 /
  "스윕"=MBC). 같은 시리즈 6/8~10 박스는 양 문서 모두 원정 MBC를 첫 행으로 기재 —
  6/18·19만 MBC 문서가 라벨을 스왑한 비정상 케이스. 나무위키 상대전적(MBC 7-0-15 vs
  롯데)도 우리 데이터(MBC 5-17)보다 MBC +2와 일치.

  `(1985, "06-19") = {"LT": 2, "MBC": 4}` — 팀코드 기준이라 merge가 어느 버전을
  남겼든 최종 스코어 방향이 강제된다.

### 교정 2: 7/14 CB-OB 유령 DH (DROP_BOXES 신설)

- **문제**: OB 문서가 7:5, 청보 문서가 7:6으로 **서로 다른 스코어**의 단일 박스씩만
  존재 — merge_games가 "다른 스코어 = 진짜 더블헤더"로 유지해 CB/OB가 각각 111경기
  (+1경기/+1승·+1패), CB-OB 매치업 23개가 됨.
- **증거**: 당일 스케줄상 동대문에는 CB-OB 1경기만 (구덕엔 HT-LT 별도 경기). 진짜
  DH라면 한 문서에 박스 2개 또는 양 문서에 각 2박스씩 존재해야 하나 각 1박스.
  청보 문서가 선발 투수(장명부/계형철)·승패(정성만 7-9 승, 최일언 6-10 패)까지 상세
  기록하고 헤더는 "위닝 시리즈" — 청보 7:6이 정확.
- **교정**: `DROP_BOXES = {1985: {("07-14", "OB")}}` 신설 — `drop_box_fixes`가
  merge 전에 해당 (date, team_doc) 박스를 폐기해 청보 문서 박스만 단일 경기로 남긴다.
  스코어 교정(SCORE_FIXES)으로는 박스 수가 줄지 않아 분리된 메커니즘이 필요했다.
